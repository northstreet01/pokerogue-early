## 最新实施顺序

1. **获取蛋与扭蛋**：补齐券来源缺口，在原大厅接可写扭蛋；沿原机器、概率、保底、批量和容量规则，可靠提交扣券/产蛋/统计后播放动画。单人和合作读取同一份本人库存，禁止另建一套蛋系统。
2. **合作进度与局外孵化**：合法过关推进本人蛋；满进度只保留待终局。通关或双方全灭确认后局外孵化，固定结果、库存移除与原收藏/IV/蛋招/统计可靠入账，覆盖断线、磁盘失败及重开；暂停和临时返回不触发。
3. **原版道具与交互补齐**：先收敛奖励可用性，再逐机制接回忆、转移、持续效果、形态/融合和地图选择；按实际支持范围交付，不将全套原版功能写成已完成。其他模式另行明确范围。
4. **辅助技能专项收尾**：队友治疗、协助和其他双打目标选择/效果/展示，区分迁移缺失与原版(P)/(N)。此项按用户要求排在以上功能之后。

Android、版本/内容指纹和发行体验仍在后续，不插到蛋流程之前。阶段验收包含真实原规则、存档失败/恢复、相关UI和代码审查，不重复重跑无关全套。

## 已接通永久成果，后续接蛋进度

2026-10-28房间共享选队已实现：新房间合并双方图鉴的可选范围，各自永久图鉴独立；按物种跨席互斥，形态/闪光不另算，取消选择释放占用。共享属性、性格、IV和蛋招仅用于本房间选队，折扣沿其中一人的原版计价，不累加捕获次数。双方须使用新版并新建房间，旧房沿原选队方式恢复。永久成果已接通新房间的原规则事实、房主持久授予、本人收藏/账本原子提交及ACK重试；旧房不补奖。蛋阶段未开始。联机本人HP/经验栏的显示修复已交付，见当前验收。

永久成果复用原setPokemonSeen、setPokemonCaught、setPokemonSpeciesCaught、updateSpeciesDexIvs和成就/券发放语义。双方开局配招仅在各自永久图鉴也允许时记住偏好，不保存房间借用的形态或蛋招权限。原蛋方法、孵化统计及库存保留仍需下一阶段审计。

成果必须有真实来源与归属；复用FormalRoomStore grants/grantAcks、快照消费者、个人IO和repository。先房主持久化，再本人收藏/账本同事务，再ACK。核对hostId/runId/seat/profileId和私有凭据，相同id异内容拒绝；不从夹具、实验奖励或无凭据旧房补奖。

按[存档约束](local-meta-architecture.md)接原EggLapse进度、库存保留、待终局队列和恢复去重。满进度仍可推进后续波次，不重复排队、不无限扣减、不在局内生成或孵化。

须用真实原规则、GameData、FormalRoomStore及双WS验证捕获/遇见/IV/进化/券/蛋事实；覆盖写盘失败、ACK丢失、重发、乱序、切档、租约失效、库存分叉与主机重启。改变schema要明确迁移，不能偷偷增字段；对旧数据的保护副本属于数据保护，不等于堆放旧安装包。
