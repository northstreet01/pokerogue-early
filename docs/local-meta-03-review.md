# 局外第三批：档案大厅与原单人保存绑定

2026-10-26，用户明确授权接入。基线为局外第二批 `23ef759c`，本批开始工程 HEAD `387077de`；期间另一窗口仅提交 VS24 工程记录 `f90aee33`，保留其全部内容。本批只在 early 实施，未创建或联系 agent，未修改真实档案、房间、正式服务或隧道，未合并、推送或部署。

## 实现范围

初始界面复用 HomePhase、原 Title 菜单、FormModal 窗口和输入框；新增档案选择、新建／改昵称、旧资料迁移预览与确认／取消、三个历史槽位及归属确认、完整个人备份导入／导出、原点／自动备份／恢复前快照。头像目前保存默认项，没有新增头像选择器。新建通过原 GameData 初始化，原物种收藏和蛋招式规则不另造默认数据。

激活档案需要明确操作；没有激活档案时继续旧入口，不自动搬迁旧资料。浏览个人收藏、蛋和券复用原只读界面，使用所选档案读取，不持有写者或改统计。显示待终局孵化数量，但本批不生成／消费合作保留蛋；存在保留蛋时阻止进入可消费它们的原单人流程。

新增每个 GameData 实例不可重绑的 IO 端口。原 `loadSystem/getSession` 与 `saveSystem/saveSession` 读写同一 profileId，沿用第二批的 revision、租约、事务和备份。切换活动档案不会改变已打开游戏的绑定；失效写者停止输入，旧回调不会写到新档案。退出先排空 GameData 保存队列，再关闭档案端口和释放写者；失败提供明确的未保存返回，禁止把关闭端口当作成功保存。

正式合作选队读取所选本人资料；席位本机凭据附带 profileId，恢复拒绝另一档案的席位，旧无绑定席位只在旧入口恢复。本批没有把实验收藏接入正式系统，没有新增永久 grants，也没有改变权威伤害、奖励或成长规则。

## 保存边界审计与适配

- 原 `saveSystem` 序列化提取为 `captureSystemData`，字段／大整数编码保留；原设置仍是本机偏好，不作为在线身份。
- 原新遭遇先保存 System 再保存 Session，第二步失败可能留下半份边界。本批绑定档案后通过 `saveEncounter/saveAdventure` 在一个 repository 事务提交两份原快照；失败保留上个完整检查点，重试后才继续遭遇。旧入口保留原顺序，补足失败处理；原合作的 `deferEncounterPersistence` 继续绕过个人单人保存。
- 原战斗中捕获／经验／奖励累计留在原模型，遇到下一保存边界时用原 `getSessionSaveData` 和系统快照一起提交；未新增中途回合检查点，不承诺退出能保存尚未到检查点的操作。
- 原 GameOver 清槽在前、统计保存于后。新档案把清槽标为待提交，在同一笔 System 保存中删除该槽并保存终局统计。写盘失败不删除旧冒险，原重试闭包不重复累计终局统计。旧入口终局行为保持兼容。
- 原系统单文件导入会使活动档案的收藏和冒险分叉，绑定档案后引导回局外导入完整个人包。未绑定旧入口继续兼容原工具；原三个槽位的新开覆盖仍沿原确认界面。
- 迁移读取旧库但不删除／改写来源。原 `loadSystem` 合法更新本机性别设置不等于来源收藏被迁移写入。

顺带修正原 GameStats 将神话孵化数错误取为神话捕获数的反序列化字段，独立断言两项不同值，避免迁移后显示统计丢失。

## 失败历史

1. `ui-a` 7/14、退出1：合成 scene 缺少原设置所用 trainer 显示端口；另一个故障注入在取得租约前就触发。补正确夹具和故障时机，没有削弱原规则或存储校验。
2. `target-a` 67/68、退出1：迁移后执行原 loadSystem 会合法更新本机性别设置，测试错误地要求所有 localStorage 不变。把完整来源只读断言放在迁移完成／启动原读取前，之后仍检查旧收藏及三个槽位未改写，并单独断言原性别设置。
3. 候选 `target-b` 独立185/185、退出0，108307.4914ms；候选类型与生产构建通过。随后收尾审查补齐退出等待 GameData 队列，因此这些候选结果不冒充最终结果。
4. `native-a` 63/77、退出1，67737.9163ms；14个失败全部为本机 WebSocket `connect EACCES`，游戏逻辑尚未进入。保留原日志，允许回环测试网络后重新独立跑最终相关整轮；没有放宽断言或超时。
5. `target-c-interrupted` 在旧首页测试第67项后等待不结束，人工停止父进程退出1。旧测试用三个固定 timer tick 驱动原UI过渡，新增档案目录的异步读取后可能错过真实待决过渡；改为有界等待实际过渡的resolver，不改变过渡顺序和过期导航断言。该轮不能称为完成或通过。
6. `target-d` 11文件独立264项中256通过、8失败，退出1，239309.1457ms；八项均是 next-battle 合成场景没有提供新 `saveEncounter` 端口，实际得到 RUNNER_FAILED 或等不到快照。原冻结参考仍使用旧两个保存端口，夹具同时补充新成对保存端口，均为此前同等的无副作用显示／存储端口，没有改伤害、生成、参考或断言。最终仅复验这份夹具与改动的原首页／新档案UI三文件，不能将修订前256项与复验相加称为新整轮264通过。相对 b4f0e78a 最终源码仅该测试夹具变化，生产文件无差异。
