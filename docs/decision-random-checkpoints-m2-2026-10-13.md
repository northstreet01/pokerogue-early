## 实现

- 检查点 payload 升级 v3：保留非空原 TurnCommand、缺属性/显式 undefined、强制招式参数及 Counter/Mirror Coat 的 `-1` 目标哨兵；v1/v2 明确拒绝，不覆盖旧保存。
- `wait-target` 保存已选命令及待选目标，恢复后选择或取消，不重新准备强制队列、不重复扣 PP。原 `SelectTargetPhase` 回调提取后回接单人，保留回调捕获的原命令引用。
- `wait-switch` 保存要求替补的席位、离场 ID 与各自合法队员 ID。拒绝选择队友或 reserve；未实现原 SwitchSummon 执行，测试只验证待替补状态与权威续行参数。
- `learn-move` 保存精灵 ID、待学招式、替换/跳过选项；需可信招式目录，缺失拒绝。提取并回接原 LearnMove 的已有招式/空槽/选择分支；替换返回原“清空槽后重新进入学招”的续行描述，不伪造形态变化钩子已执行。
- Node `withOriginalRules(context, callback)` 用 AsyncLocalStorage 隔离场景 RNG 与奖励池表。原 Utils、Battle 等级、Move、Modifier、物种及场景种子入口已改接；浏览器保持 Phaser 原流。嵌套种子作用域不更换全局 RND，异步交错互不串流；结束后的遗留回调拒绝取数。Node 无上下文或调用非种子随机会拒绝。
- 原 ModifierType 的八张阈值/忽略索引表改为房间状态并纳入检查点。原阈值重建会调用生成器并消耗随机数，恢复时直接还原表，不能重新计算。野生/训练家继续共享原来的敌方池位置，不改变原选择顺序。

`Math.random` 调色板量化属于显示代码，未纳入服务器规则路径；局外抽蛋、档案迁移及动画随机不混入战斗流。新 host 尚未作为完整原运行器接到正式开局入口，正式缺适配器仍拒绝。
