## 代码审计与方案

原 Home.navigate 与合作退出均 location.assign，单机／联机 HTML 各建一个 Phaser.Game；同一页缓存无法跨文档保留已解码纹理与音频。改为一个 Game 内创建新的原 BattleScene，退出旧场景、保存／释放原 GameData、清理输入与旧连接；全局纹理／音频／动画／pipeline 缓存保留。每个新场景有独立 Phase、计时器、输入和不可重绑的 profile IO，退役场景不能排入新阶段或抢占UI。底部联机入口也使用同一条导航，保留旧入口的回退行为供兼容测试。

原首页为了清残图隐藏全部战斗对象但没有大厅背景。本批用原 town_bg 单独展示大厅，不复用旧战斗的 arena／精灵／HUD，原 Title 菜单与窗口保留；标题与档案信息不再重复堆在同一位置。

原预加载对每次入口都枚举全部地图和训练家。大厅与合作等待只加载 town／plains 与共用UI；合作在场景展示前用原地图别名／底座／props路径加载当前地图，训练家仍走原 TrainerConfig.loadAssets。单人暂保留原完整地图／训练家预加载以兼容原流程，热进入跳过已缓存资源。删除唯一未被任何游戏代码使用的远端 rextexteditplugin 下载，原输入继续使用已打包的 rexInputTextPlugin。

原服务已有双方在线＋状态ACK屏障，但界面只是战斗页上的小面板且满员后自动拉起选队。新增明确的等待房间状态：两席加入／昵称／准备状态、未满员不可选队准备、到齐后主动选队；原共享预算／草稿／准备权威协议继续复用。新增 roomPresence 仅显示服务端已保存的席位名，不携带恢复token，不改规则检查点。

原 WS 固定 location.host，服务端只接受同源浏览器；原 seats/outbox 只以 origin/room/seat 标识。新增本地主机身份文件 host-id.json（坏文件拒绝、不重建）；通过只读 /coop/v1/host 发现，地址变化不能改变 hostId。新绑定按本机origin＋hostId＋profileId隔离，出站行动保留原actionId/runId/包。恢复还需原席位token，并在模型消费与ACK／outbox重放前核对已存runId。旧同源恢复走明确legacy入口，不改前缀搬运旧outbox。

用户本地入口保持不变，房主地址只用于fetch／WS；不跳转到房主网页或发送完整个人备份。跨源浏览器默认仅接受本机HTTP loopback客户端，额外来源需房主显式COOP_CLIENT_ORIGINS；HTTPS页面不能绕过混合内容限制。新增本地启动命令默认只监听127.0.0.1，--host由用户显式选择LAN监听，不改防火墙、不安装虚拟LAN或开隧道。
