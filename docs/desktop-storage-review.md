2026-10-26，用户在第一批 EXE 之后再次要求继续施工。范围是转型路线第二段，不是原局外第五批。用户随后指定参考《杀戮尖塔 2》，对照见[参考记录](slay-the-spire-2-reference.md)。

## 实现

Electron main 独占 `userData/storage/personal.sqlite`，使用 Electron 内置 Node SQLite、WAL、FULL 同步和数据库事务。个人档案、历史、迁移凭据放在 meta，席位、outbox、旧版单人存档和设备偏好各有独立 scope。房主合作房间继续保留在 `hosts/formal-rooms`，本批不改房间协议或规则。

renderer 保留 repository 的原校验、租约和档案 revision。跨 IPC 发送明确的读取集合、数据库 revision 和改动集合，在主进程原子比较并写入；冲突后重新读取且重新执行同步变更，最多重试八次。没有传函数或开放 SQL、文件路径及任意文件操作。全库 revision 不能代替档案 revision 或单写者校验。

设置、教程、语言、已连接房主和自动恢复暂停标记接入同一数据库。启动前尚未迁移时读取原偏好，迁移后写入 SQLite；会话级动画去重仍留在 sessionStorage。浏览器没有原生桥，继续使用原 IndexedDB/localStorage。

## 迁移与恢复

首次读取桌面资料时只读捕获原三份 IndexedDB 和五项设备偏好。非空旧资料弹出确认；取消留在入口，重试可以再确认，不创建空档替代。确认后再次捕获并比较；主进程验证一次性迁移票据、数量和摘要，一次事务发布。失败则回滚并允许重试，既有新库不会被旧库再次覆盖。原档案使用原 serializer/codec 验证，旧记录保留原键和值。

该迁移只覆盖同一桌面应用来源的资料，不能读取 Chrome 等外部浏览器的私人数据库。外部浏览器仍通过已有显式个人备份导入。未知 schema、损坏数据库或无效旧档案报错，禁止静默创建新档覆盖。

菜单“备份个人存档数据库”生成一致 `.sqlite` 副本。“恢复个人存档数据库”先要求确认并等待 renderer 保存，停止房主后验证备份，生成当前库保护备份，再原子恢复并重启；不能把正在写入的 sqlite 主文件单独复制当完整备份。恢复移除旧写者租约，并抬高数据库 revision 拒绝旧请求。备份含本人私有席位，不能分享为邀请码；房主房间必须另外停机备份。
