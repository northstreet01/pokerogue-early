# M3 第三批：原玩家招式选择与网络意图校验

2026-10-13，基于 `5fe230f2`。M2/M3 仍部分完成。

## 实现

`fight-command.mjs` 的 `selectFightCommand` 提取原 CommandPhase 的 FIGHT 选择分支，原单人已回接。保留 trySelectMove、无可用招式时挣扎、内部 cursor=-1、ignorePP 与位置参数覆盖、无招式时自身位置、单目标/多目标/全体目标选择行为。返回原命令和是否需要选择目标；禁用招式提示、选择目标 Phase 与原队列操作保留在显示层。

`resolveFightIntent` 只接受 kind/pokemonId/cursor/target，拒绝额外字段、错误实例、越界槽位、非法目标、死亡精灵及待继续的排队动作，不允许输入端指定 ignorePP 或内部 args。目标来自可信 getMoveTargets 提供者；无需选择目标时要求 target=null，不从客户端接受任意目标集合。验证不消耗 PP，不提交战斗状态。

该接口不是全量合法行动生成器：Encore 等强制选择必须由原运行器先处理，协议接入仍应先按权威合法选项校验。换人、捕获、逃跑未在本批分离；排队动作路径仍由原单人 Phase 执行，正式合作尚未支持。

## 验收

- 冻结参考来自 `5fe230f2:src/phases.ts` 的完整 handleCommand，测试只进入 FIGHT 分支。
- 320 组当前实际 Phase 与原方法差分，覆盖可用/不可用招式组合、挣扎、内部跳过 PP、内部空动作、不同参数位置、空目标/单目标/多目标/全体目标；比较返回值、调用顺序、提示和目标选择 Phase、命令内容。
- 网络校验拒绝冒用精灵、负/越界槽位、错误目标及伪造内部参数；检查 PP 不变。
- 实际原 Pokemon 检查点恢复前后产生相同单次/全体目标命令。
- 既有真实 WS 等待行动测试改为提交 fight 意图：在权威合法选项匹配后，用已恢复的原 Pokemon 校验。单方提交后服务重启、损坏持久输入及写入失败恢复继续通过。目标提供者和后续结算仍是测试适配器，不是完整原战斗运行器。

合计 108 项自动测试、类型检查和生产构建均通过；构建仍有既有的大包和混合导入警告。未执行浏览器 UI 或真实双机验收。

下一批继续强制动作与目标决策状态映射，并推进 MovePhase/MoveEffectPhase 的 PP、命中和效果执行分离；不能将本入口当作全量服务器运行器开放正式游戏。
