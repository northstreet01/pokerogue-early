# 第四批本地启动与进入流程测试

两个人各自在自己的设备启动本地入口，收藏仍留在各自浏览器。房主设备运行现有权威服务；不用在线账号，也不用我们托管业务服务器。当前是本地网页／Node运行方式，完整离线发行包仍在后续批次。

## 启动

先在 `E:\pokeregue\pokerogue-early` 构建原Worker和前端：

```powershell
npm run build:coop-runtime
npm run build
```

每位玩家的本机入口：

```powershell
npm run start:local
```

打开 `http://127.0.0.1:8020/`，在原风格大厅选择本人档案。固定使用同一个协议、主机名和端口；`localhost` 与 `127.0.0.1` 是不同存档来源。迁移旧隧道域名里的个人资料，须先从原地址导出完整个人备份，再在本机入口确认导入；不会自动跨站读取。

房主希望允许同LAN／用户自建虚拟LAN访问时，主动采用：

```powershell
npm run start:local -- --host
```

`--host` 表示监听局域网接口；不自动配置防火墙、n2n、路由转发或公网隧道。加入者保持自己的本机入口，在联机页面填写房主的实际HTTP地址，例如 `http://192.168.1.8:8020`。不要打开房主网页来当作自己的本地账号入口。

默认接受同源和本机HTTP loopback客户端；若客户端网页确实从其他LAN来源打开，需房主显式设置精确来源列表：

```powershell
$env:COOP_CLIENT_ORIGINS='http://192.168.1.20:8020,http://192.168.1.21:8020'
npm run start:local -- --host
```

不支持绕过浏览器HTTPS／HTTP混合内容限制。局域网HTTP房主测试请从自己的本机HTTP入口启动；HTTPS客户端需要相应HTTPS房主。

## 进入与等待房间

1. 大厅应有原城镇背景、中文标题和原风格菜单，五项入口可见，没有上一局的精灵或HUD。
2. 大厅进入单机／联机、退出返回大厅，应保持一个游戏画布与资源缓存；第一次单人进入仍须加载原单人地图／训练家素材，不能将热切换优化理解为所有首次下载消失。
3. 联机先核对房主，再创建或输入房间码加入。未满员时显示两席加入状态，只能等人或退出，不能准备进入战斗。
4. 双方到齐并完成模型同步后，主动点“选择队伍”进入原版选队。完成原确认后保留原准备流程；双方准备成功才进入战斗。
5. 选队的房间提示应位于游戏画布外侧，不遮挡第一排宝可梦。退出按钮仍可用；反复选择、取消和返回不能重复创建房间或监听。
6. 联机退出只离开本人并暂停本机自动续局，房主文件和已提交行动保留。大厅“恢复已有联机”按本人档案列出席位；它不是房主完整存档备份界面。

## 重连与数据保护

房主身份保存在合作数据目录的 `host-id.json`，完整房主备份需要与房间JSON一起保留；包含私有席位token的房间文件不要分享给其他人作为邀请码。移动房主地址时使用同一份完整目录，客户端识别同一hostId，恢复原run／席位后才重发原行动。

若相同地址已经换成另一台主机，恢复应停止；不同主机／档案的席位与outbox不会因为房间码相同而混用。旧同源席位从明确的旧恢复项进入，不改键前缀自动搬运。

已加入的房间断线后会重试连接；房主服务尚未启动时身份探测也要继续重试，退出必须能立刻停止旧重试。尚未加入任何房间时，连接失败保持手动改地址，避免不断重建输入框。

建议真人复验：大厅与两模式往返三次；一人开房／队友迟到；双方选队／准备；至少一次真实FIGHT；一端退出后另一端显示掉线；原席位恢复；房主关闭再重启同目录；改端口连接同hostId；错误地址／不同主机停止恢复。真实两设备LAN／虚拟LAN与声音没有实际执行时，仍应记录为待验。

合作永久成果、蛋进度／待终局孵化、正式扭蛋消费仍在第五／六批；本批不声称这些资源已入本人收藏。验证范围与失败历史见[第四批验收](local-meta-04-review.md)。
