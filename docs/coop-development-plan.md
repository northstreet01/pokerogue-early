## 接下来执行方向

M3 剩余工作分为五部分（分组不代表等量工期）：

1. 伤害后的待续流程：Damage 展示收尾、StatChange、多段续击、Faint、替补和胜利停点。
2. 完整回合闭环：连接已验证出招／伤害／MoveEnd／TurnEnd，到下一次行动输入，补全程恢复差分。
3. 非 FIGHT 实际执行：捕获、换人、逃跑及双方所有权校验。
4. 复杂机制覆盖：特性、持有物、天气／场地到期、状态、形态、Boss，优先复用原规则。
5. 生产服务器运行器：房间隔离的无渲染场景、合法行动／目标校验、完整 RNG 绑定和正式 `/coop/v1/ws` 接入。

下一轮优先完成第 1、2 部分。原合作 UI 属于 M4／M5，不计入以上 M3 剩余项。

所有 M3–M8 切片先执行 [SPEC 第 4.5 节复用清单与约束](../SPEC.md#45-复用优先与后续开发约束)。当前清单是已核对的复用候选：early 原规则/UI/收藏、M1/M2 基础、此前项目大厅/行动采集/回放和测试；尚未因此新增移植完成项。每批记录“已复用、待适配、未复用及具体原因”，优先调用/迁移已有逻辑，只新增必要适配。此前 pokerogue 目录只读，不整套迁入 Host 权威与轻量快照。

1. 保留已有出招／伤害、独立 MoveEnd／TurnEnd、advanceQueuedRulePhase、v6 codec 和任务观察器；先接 Damage 展示收尾（不能再次扣 HP）、StatChange 和多段续击，再适配 Faint 替补／胜利停点，连成完整回合。复用现有双端 harness，审计新生成引用，不替未确认的经验归属或同回合全倒下规则作决定。
2. 扩大原进场特性/场地、接棒持有物、形态、AI 和非 FIGHT 执行差分；不得把当前无这些效果的换人测试夹具当成全量规则验收。
3. 每个执行切片继续原版单端差分与真实 WS 两端恢复/故障矩阵；随机目标提供者不得在纯校验中消耗权威 RNG。
4. M4–M6 接原 UI、整备及永久收藏；M7 持久化加固贯穿，M8 保留真实双机与长局验收。正式运行器缺失时继续 ADAPTER_UNAVAILABLE，不回退实验引擎。

## 进度维护规则

每次交付更新本表与 SPEC 第 5/7 节，记录模块编号、改动文件、实际测试、已知缺口、提交号和推送状态。类型、运行时实现、自动测试、浏览器验证、双机验收分别登记；只完成其中一项不能将整个模块标成已验收。

复用记录同时遵守 SPEC 第 4.5 节：来源路径和提交/未提交状态、复用部分、接口差异、验证结果；不复用候选须给具体原因，不重复开发已有 M1/M2 基础。

未确认玩法见 SPEC 第 8 节。可继续开发通用契约和状态基础，但相关规则落地前需确认，不能凭实验实现自行决定。
