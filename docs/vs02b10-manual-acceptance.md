在PowerShell中：

```powershell
Set-Location E:\pokeregue\pokerogue-early
npm run build:coop-runtime
npm run build
$env:COOP_PROFILE_LOBBY='1'
$env:COOP_DIST='dist'
$env:COOP_FORMAL_DATA='build/user-vs02b10-rooms'
$env:COOP_DATA='build/user-vs02b10-legacy'
$env:PORT='8047'
node server/start.mjs
```

端口已被占用时改用空闲端口，不结束其它服务。两个独立浏览器／profile打开 `http://127.0.0.1:8047/coop-play.html`。使用真实原StarterSelect，各自1–6只、个人10／共享14点及本人折扣；不改存档或运行时数值，不调用隐藏方法跳阶段。满员场景需通过合法选队或正常捕获达到本人6只，不能用Master Ball合成测试夹具冒充浏览器验收。

方向键／WASD移动，Enter确认，Esc取消，C完成选队，M菜单；鼠标继续使用原菜单输入。

## 未满6只的捕获

1. 原选队→双方准备→双方真实战斗；满足原捕获条件后用原BALL菜单投球，可先取消再重选。
2. 失败时只扣本人一次球，不新增成员；双方能继续合法行动。
3. 成功时新个体直接进入捕获者随身队伍，不替换当前前场，伙伴不获得。本人队伍不超过6只，没有新的“无限备用仓库”或分页换队按钮。
4. 用原Party／摘要核对新成员名称、等级、HP、状态及招式／PP。后台自动测试另核对完整IV／性格／性别／特性／形态／闪光等字段，摘要没有显示的字段不要写成已从画面验证。
5. 战后跳过或领取已支持奖励、双方准备；原战前选择新成员出场，下一战本人及伙伴实际FIGHT。刷新一端后人数、球数和个体不重复变化。

## 已满6只的捕获

1. 正常捕获成功后应停在原确认框：接纳需要放生现有合法队员；拒绝则放弃新捕获。
2. 选择接纳，打开本人原Party。不得显示伙伴的队伍；原满员捕获专用放生允许选择本人的当前出场者。摘要只读查看后能返回；此时不能在浏览器先删成员。
3. Esc取消Party，应回到取舍询问，不扣第二颗球、不释放任何成员。重新进入后选合法成员；最终放生确认选否，能继续重选。
4. 最终确认后只有选中的本人成员被放生，新捕获加入，最终仍为6只。伙伴资源／队伍不被该选择改变；原战斗本身合法产生的经验变化另行观察。
5. 另跑一次放弃新捕获：原6只保持，球已在投球时消耗一次，不退球也不再次扣球；原胜利／整备继续。
6. 在取舍询问或Party界面刷新一端，应恢复到同一待处理捕获。可关闭本测试服务后按相同环境变量、相同数据目录重启，再刷新两端；不能重投球、重复放生或增加第7只。
7. 整备双方准备，原战前选择接纳的成员，下一战实际FIGHT。若期间遇到尚未接入的成长／特殊机制，记录准确停点，不能通过改值或跳过阶段补成通过。
