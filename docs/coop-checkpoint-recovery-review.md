# 复活后伤药报错与检查点脱离验收

2026-10-26，用户在8034手测报告：购买活力碎片复活后，再使用伤药触发RUNNER_FAILED；要求支持从回合存档重新进入。本轮只修故障、补脱离入口、记录并交接，不推进局外第五批。基线72b9ac4d，工作区开工干净，只early，不创建或联系agent。

## 复现与根因

只读发现用户8034房间84D87A在revision34、原第4波整备处保留了失败输入。私有诊断副本仅放ignored build/revive-recovery，不提交房间、token或个人档案。房间最后待结算的操作实际是席位2领取免费POTION；复活与治疗本身正常，完成整备后进入原第5波训练家战才失败。

先用真实Worker适配器重放副本，稳定得到ORIGINAL_RUNTIME_FAILED。再在独立诊断进程执行同一原模块得到精确栈：NextEncounterPhase → Trainer.loadAssets → TrainerConfig.loadAssets → BattleScene.loadAtlas，读取不存在的textures.exists。第四批新增浏览器素材缓存检查，但服务器无渲染的scene绑定遗漏该缓存端口。此前只到首战第2回合的浏览器验收没有覆盖第5波，306相关轮也未含自然训练家进入测试。

修复为native scene增加显示专用的空textures与audio cache查询端口（exists返回false），继续走原有有界空loader，不跳过训练家生成、原Phase或规则。修后同一故障副本通过真实Worker恢复、校验、推进与新检查点校验，到wave5／wait-actions。原房间文件未被诊断程序改写，修复不需要改档。

## 自动存档与脱离语义

原单人saveEncounter在遭遇处保存，不是每回合存盘。正式联机本来就由FormalRoomStore在每个安全决策节点，以及接受输入／回执时原子写入、sync后rename；粒度细于每回合一次。前端单独保存HP或另加一份手动战斗存档会造成两端权威分叉，因此继续复用现有检查点。

新增常驻“卡住脱离／重载存档”，放在可替换的决策控件之外。它不等待旧消息／菜单队列，调用有界场景退出并用原hostId／room／seat重新进入；凭据仍在本机IDB，不进入URL。已完成购买、扣款、复活、奖励和随机状态都保留；已接受但尚未结算的操作继续待结算。它从最近安全节点恢复，不声称从动画任意一帧恢复。

若RUNNER_FAILED持续复现，双方当前席位可分别点“确认撤回失败行动（需双方）”。服务端校验身份、run、连接epoch、revision和decision；仅运行器故障开放，不允许对存储故障强行清除。单方或同席重复确认无效。双方确认后保留已提交检查点、全部回执和grants，只清空从未提交成功的候选输入／展示事件，增加revision并要求双方重新ACK。旧actionId继续返回旧回执，不会在新选择处再次执行。断线／替换连接／重新同步会清除未完成的确认，写盘失败保留旧内存与磁盘状态。

不是任意历史回滚、回档刷道具、永久grant修复、损坏存档修复或所有游戏bug的兜底；确定性错误仍需修代码，丢失主机文件或本机席位凭据也不能靠按钮恢复。本轮只为正式联机补入口，没有新增单人逐回合存档。
