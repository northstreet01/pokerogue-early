调查日期：2026-10-13（北京时间）。本次使用之前从 pagefaultgames/pokerogue 获取的 Git 历史，检查原版 main 的第一父链历史快照、源码、package.json、随机数与存档路径。另查询了原版 GitHub 页面。本次没有修改当前游戏代码、切换分支、安装旧版依赖或覆盖未上传改动。

5 月底的 src 膨胀很大一部分来自内置多语言；排除翻译后，它的核心源码为 5.56 MB，不能简单用 411 对 129 宣称战斗复杂度增加三倍。该快照有简体中文，可作为需要旧版中文资料时的参考；不建议为中文直接搬进它的整套新机制。

## 为什么选择 3 月底

1. 相比 2023 年的原型，已经具有更完整的经典战斗、训练师、捕捉和存档流程；也已经出现 Vitest 配置与基础测试文件。但现有旧测试并不能证明战斗稳定。
2. `src/battle.ts` 已有 double、battleSeed、battleSeedState 与按回合播种机制；`src/battle-scene.ts` 有 executeWithSeedOffset。双打合作不必从零实现这些基础。
3. 没有后来的 Mystery Encounter 系统。原版 2024-09-13 的 `acb2b66be` 才加入特殊遭遇；可避免当前已经遇到的一大类多分支交互同步问题。
4. 核心文件比当前基线少很多，Pokemon 文件约 2,729 行，而当前基线约 7,153 行。适合逐条梳理行动、事件、状态、随机数和换人的边界。
5. 原始图片、音效等 public 资源在同一历史树内；应使用该提交的资源，不混用当前新版资源子模块。

不优先选 2023 年最初提交：虽然 Phase 少，但该快照没有找到上述成熟战斗播种接口，且没有测试基础。为了轻量退到非常早的原型，会增加补齐基本战斗行为的工作。2023 年 11 月底也可作为更激进的精简参考，但不作为当前首选。

## 该版本仍须注意的实际情况

- 它仍有融合、孵蛋等机制，不是天然的极简引擎。第一阶段应从入口控制开放范围，再逐步梳理模块，不一次性大面积删代码。
- 没有该快照的简体中文资源；可先汉化基础菜单、行动和联机提示，之后再补完整文本。
- 默认 `src/battle-scene.ts` 的 bypassLogin 为 false；`src/system/game-data.ts` 已有 bypassLogin 对应的 localStorage 存档路径。首次落地需要单独改成本地单人启动，并检查统计、排行等额外 API 请求。
- 旧版 Phaser 为 ^3.70.0、Vite 为 ^4.5.0、TypeScript 为 ^5.0.3；不能复用当前项目的 node_modules。先保留旧锁文件，实测安装和启动后再逐项调整工具链。
- src/utils.ts 仍存在 Math.random；有种子不代表整个引擎的所有路径都已经确定。必须审计调用路径，并将画面、时间、UI 输入与战斗结算分开。
- 使用独立端口隔离浏览器存档，不让旧版读取当前游戏的 localStorage。不要自动导入新版存档。
- 本次仅做历史与源码审查，未安装、构建或完成旧版游戏实测。不能称为“已验证稳定版本”。

## 逐步实现顺序

### 第一阶段：只验收独立单人基础

固定上述提交，独立目录、端口、依赖和存档。先跑通普通野生战斗、训练师战斗、主动换人、倒地换人、捕捉、奖励和下一波。合作入口暂不开启；不要先把当前 LAN 代码整套移植过去。

### 第二阶段：最小双人房间与固定战斗

重写一个小型独立房间服务，提供创建、加入、准备、开始。先固定两位玩家各一只精灵、固定敌方双打、普通招式。服务端收齐同一个回合的双方行动后再结算，等待双方确认完整权威终态，才能进入下一回合。定义消息版本、房间、波次、回合和请求 ID，拒绝过期或重复输入。

战斗架构优先将选定范围的结算抽成可测试模块，由独立服务器结算并发权威状态和事件；抽离完成前，可以固定由 Host 执行一次结算，服务器做回合协调，但须准确标为 Host 权威。不要在尚未证明确定性的情况下让两端各自计算后继续推进。

### 第三阶段：一类机制通过再增加下一类

按主动换人 → 倒地换人 → 异常状态/天气/场地 → 胜利奖励及下一波 → 捕捉和队伍变化 → 学习招式/进化 → 特殊变身等顺序增加。每类都必须覆盖跨回合、中途交互、状态快照与双方确认。双方校验不一致则停止，并记录可重放的种子、初始状态、行动和事件日志，不能跳过确认继续游戏。

后续需要逐步将这套“小范围已验证的战斗模块”扩展，而不是继续在现有 2026 大版本上追加补丁。
