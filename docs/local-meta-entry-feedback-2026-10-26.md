# 局外进入流程反馈：2026-10-26

用户实测指出三处未完成体验，按第四批优先范围处理；本记录不表示已经修复。

| 问题 | 当前原因／边界 | 修改策略与验收 |
|---|---|---|
| 初始页面背景全黑 | 之前隐藏战斗背景、前场和HUD以清除退出残图，却没有补正式大厅画面。第三批只接档案与原菜单，不算完成大厅视觉 | 先审计原版可复用的背景、窗口、标题／训练家与菜单BGM，形成统一大厅；退出后没有旧战斗残图，建档和个人浏览仍在同一套视觉中 |
| 选择单机／联机像换游戏，并有很大的重新加载 | 现 HomePhase.navigate 使用 location.assign，两个入口重新创建游戏／Scene，不能跨文档复用已解码纹理和音频；缓存不等于无需重建 | 固定本人本地入口，优先在同一游戏实例通过原Phase／UI进入，保留共用已加载资源；正确清理旧phase、输入、回调、音频、连接与档案写者。关键素材先就绪再露出场景，进度真实可返回，不能一次加载全部图鉴来掩盖切换 |
| 尚无联机待机房间 | 底层满员／选队保护不等于完整的可见房间大厅；原入口仍缺正式等人页面 | 开房／加入后先显示房间、本人／队友加入与断线、昵称／选队／准备状态、退出与重试；未满员不得启动，满员后按统一准备状态进入。不得为了等待队友先进入战斗或重复创建房间 |

实施顺序：第四批先完成统一大厅、进入切换与待机房间，再接各自本地档案连接房主、端点与重连；第五／六批仍为长期成果、蛋和扭蛋，不抢先接入。第四批应一次交付连贯的“本地大厅→房间→等人／选队／准备→战斗→返回大厅”流程。

验证需包括真实浏览器冷／热进入耗时和资源请求、往返多次不重复监听／重建、未满员／队友迟到／退出／掉线／重连，以及本人档案不串写。没有跨设备和声音实测时仍待验，不能只用逻辑测试关闭本反馈。
