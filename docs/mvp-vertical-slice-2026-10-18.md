# 先打通真实联机：MVP 纵向切片

日期：2026-10-18。用户已明确优先“尽快能一起玩”。本安排覆盖旧的外围 QA／扩充机制优先级；原完整合作目标及 SPEC 未确认规则继续保留。

完整架构、接口、双端体验与上线门槛见 [首发设计](mvp-delivery-architecture-2026-10-18.md)。本文件保留三批交付顺序；本轮仅形成设计，未实现接缝。

## 当前事实与唯一优先项

2026-10-18 后续更新：VS-01 的 6c7f2319 已交付真实内部 adapter／投影／个人模型应用；维护者修订验收 920/920、类型／构建通过，见 [记录](mvp-vs-01-review-2026-10-18.md)。下方“尚未桥接”为设计时点历史；当前缺口是正式个人入局、原 UI、实际落盘恢复和跨设备，执行 VS-02。默认正式服务仍 ADAPTER_UNAVAILABLE。

UI-01R／QA-03 交付已验收，实际完整回归 912/912，并不代表生产链路已连通。正式服务需要八个 adapter 方法，原 Worker 暴露 native-* RPC，两者尚未桥接；正式原类 projectSnapshot／applySnapshot 亦未实现，默认 WS 仍 ADAPTER_UNAVAILABLE。

下一批只以这条链路是否成立判断进展：

`两个真实 WS 客户端 → formal 八方法 adapter → 房间独立原类 Worker → 最小私有投影 → 客户端实际原模型应用／提取 → consumer 哈希核验与 ACK → 普通下一战 → 再次真实 FIGHT`

不以新增测试数量、文件数量或再列清单代替该证据。不为首次联机贯通先补齐捕获／Boss／全道具。不另建简化引擎或整套新协调服务。

| 批次 | 具体工作 | 退出条件 |

VS-01 可以先用内存 store 和假身份／队伍夹具定位接口问题，但只能标内部接缝证明。它不能冒充跨设备可玩、真实个人档案接入或服务器重启恢复。生产接线必须在 server 真实实现中，不能把 tests/helpers 的规则 driver 挂为 adapter。夹具的小目录／固定三只不成为产品物种、世代或数量限制；当前 native 入口固定队伍形状仍是实际局限，接选队时须明确核对，不能宣称已支持任意配置。

## 初次可玩范围

- 优先开放已能承载的普通野生合作双打：双方本人行动、目标、原伤害／PP、战后经验／恢复、独立整备状态、战前本人换人、下一波。每一项必须在真实桥中接上后才写支持。
- 首个内部接缝可先用现有 skip／ready／unready 走通整备。面向玩家的奖励／购物按钮只有在迁入已有原效果切片后才开放；未接按钮明确提示暂不可用，不能假领取或扣款。不要重新写效果公式。
- 捕获、主动战斗换人／逃跑、到期蛋孵化与永久授予、特殊遭遇、训练家／Boss、复杂成长及未验证机制可以暂不开放；保留为完整合作缺口，遇到未知分支应停在可恢复边界并明确原因，不能跳阶段或静默改规则。
- 不清空真实蛋库存来伪装支持；v6 不自动补蛋、带蛋 v7 与 hatch-commit／M6 边界继续保持。未确认的券与同时全倒下顺序不自行决定。
- 不为缩小 MVP 删物种／世代，不把固定测试选择写成长期玩法限制。此处缩小的是已经实际接通的机制范围，原版合法容量与已确认合作规则仍需尊重。

## 复用与接口工作

1. 复用 `server/formal-coop-service.mjs` 的版本核对、房间串行、候选提交、投影哈希、输入持久去重、ACK／重连屏障。其八方法全部允许 async，不另建协调器。
2. adapter 只把协议／决策映射到原 Worker。复用 `server/original-rule-host.mjs` 与 `src/server/native-entry.ts` 的 submit、run-to-boundary、preparation、prepare-action、next、switch；若缺原类 codec 校验／投影 RPC，只增加薄接口，不复制原规则或把 JSON 字段检查冒充原类恢复。
3. 在 context/checkpoint 包装中保留稳定 run／房间归属、原 checkpoint 与 pending intents，失败时丢弃候选；同一房间一个独立原类模块图，不能共用全局可变模型。建房发生在第二席加入前，真实身份／选队来源必须明确接入，不把内部固定队伍 provider 当已完成的个人档案绑定。
4. shared 仅含共同战斗必要公开内容，personal 含本人队伍／资源／决策及允许的个人内容。复用已有原类 codec 与投影候选；不能直接把完整服务端 checkpoint 广播给双方。所有权、alias、隐私和客户端可重建性需同时核对。
5. 客户端复用正式 `createSnapshotConsumer`，applySnapshot 恢复真实原模型，captureAppliedState 从实际已应用模型提取，而不是返回上次收到的 JSON。只有模型核验和必要本地事务完成才 ACK。
6. 复用 [UI 清单](outsourcing/MVP-UI-01-reuse-inventory.md) 的原 handler；用薄适配采集意图和驱动显示，不让客户端原规则回调再次扣 HP／PP、生成菜单或推进权威队列。

## 执行模式与决定性风险

连续原队列作为普通生产路径；逐阶段 native-step 保留为测试／诊断路径，不从代码中删除。恢复在保存的决策安全停点重建，然后继续同一连续运行路径；遇到暂停的个人回调按原方法恢复，不从零重启菜单。

随 VS-01 做实际可达路径审计：原随机源、场景／战斗 RNG、展示回调中的模型写入、定时器和时间依赖。未知渲染或未绑定权威随机继续明确失败；规则需要的 Summon／回调副作用不能被空 stub 吞掉。只验证普通分支就只声明普通分支，不能声称 headless 与浏览器全机制等价。独立个人随机流、全生产 RNG 继续列未验收。

原类状态＋JSON checkpoint 的双表示保留，但收敛在已有 codec／恢复入口，adapter／UI 不再引入第三套战斗状态。新增机制优先复用已接切片，而不是两套公式分别维护。

## 持久化与 M6

完整收藏事务可后置，基础房间事务不能后置到可玩验收之后。已有 store 同文件持久化 inputs／receipts／checkpoint／events；接缝层还须把 `deferEncounterPersistence` 等 intent 连同候选 checkpoint 保存，不能执行后丢弃，也不能仅存进程内数组。

同候选意图需要稳定标识／归属和待处理状态，为后续幂等消费留接口；在 M6 完成前不实际消费蛋、写收藏或发永久授予，也不伪造已持久化成功。先用一个写盘失败和一个重启续局检验这层契约，避免 UI 接完后再改状态边界。

## 最少但必要的验证与测量

- 双端真实行动与实际模型提取、首战到第二战及再次 FIGHT，是本批主要证据。
- 随接缝补单方输入重启、同 actionId 重发／异内容、写盘失败、旧 epoch ACK、两房间隔离。只补与实际改动相关的用例，不另开几十项外围测试任务。
- 记录实际 checkpoint 与 shared／personal 序列化字节数，Worker RPC 往返耗时和房间进程／Worker 内存；记录命令和环境，不先定无依据的限额。bundle 文件大小不等于每房实际内存占用。
- 公开部署的限流、观测、进程／房间池、快照压缩及迁移可后续，但 VS-03 的连接地址、错误可见性和基本资源释放必须能用。
