# 项目维护与交付要求

更新：2026-10-27。只维护 pokerogue-early，使用中文，不创建或联系其他 agent。当前任务是清理过时入口、重复实现、旧构建与文档，并完成代码审查；不自动推进永久成果、孵化或 Android。

## 恢复工作

先核对实际 Git 分支、远端、未提交修改、worktree、运行进程与监听端口。不要依靠文档中的旧 PID 或历史测试数字。阅读 [使用说明](desktop-lan-usage.md)、[当前架构](desktop-lan-transition.md)、[存档约束](local-meta-architecture.md)、[当前验收](desktop-lan-review.md)与[后续计划](coop-development-plan.md)。

玩家实际数据在系统 AppData/PokeRogue-LAN，与构建目录分离。历史 build 中含用户房间或诊断副本的目录也不能按编译缓存删除。不得改动真实资料、房间、服务、隧道或防火墙；不得覆盖正在运行的 EXE、资源或 Worker。

## 每次交付的门槛

1. **先审查代码**：沿实际入口检查调用链、模块归属、数据拥有者、失败路径、资源释放和异步旧回调；核对是否仍有旧页面、第二套规则引擎、重复存储入口或隐藏的废弃组件。类型通过不等于审查完成。
2. 运行 npm run review:code：检查全部第一方源码、工具、测试的语法及相对依赖，检查生产模块是否有运行入口，发行 HTML 是否仅保留正式游戏文档。仅供测试的参考实现放 tests/helpers，不留生产目录。此脚本不能证明游戏规则、并发或产品体验正确。
3. 审查新接口的必要性，优先修正原调用链并复用原规则。注释写清职责、归属、兼容原因和删除条件；不以新增包装、兼容分支或另一页面替代迁移清理。
4. 运行类型检查和影响范围内的相关回归；有规则改动才扩大原规则差分。禁止无必要重跑全套或200波；不能拼接旧数字冒充新一轮。保存失败、重复提交、切换场景、退出和重连是涉及数据时的必查边界。
5. 前端、原 Worker和桌面壳一起构建；实际启动封装后的 EXE验证用户路径。区分单元、协议、合成界面、正常前台、声音、真人两设备及长局，不夸大覆盖范围。
6. 新包验证通过后清理旧发行包与临时副本，统一保留 build/desktop 当前开发产物和发行包。删除前核对绝对路径和运行进程；仍在使用的旧包等玩家退出后清理。真实数据和必要的最近故障证据不属于旧安装包。
7. 更新现有说明和验收文档，不再每批新增日期报告、重复交接或任务书。历史经过查 Git；新增文档须确有独立长期用途。
8. 显式暂存本轮文件，检查 diff、链接和构建一致性。SPEC及AGENT/PROMPT仅本地保留，不提交；是否推送、合并或发布按用户当次授权执行。

修复验收后交用户手测，等待反馈；不自行扩大功能批次。
