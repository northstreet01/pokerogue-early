# M2 第二批：等待行动检查点装配

日期：2026-10-13；起点 `78900705`。本批完成显式适配上下文的 `wait-actions` 检查点与验收；M2 整体仍为部分完成。提交号以本批 Git 记录为准，未推送。

## 已实现

- `decision-state.mjs` 装配前批 Pokemon/队伍、原 Battle 字段、Arena 效果与生成池、双方金额/精灵球/修饰器、敌方修饰器、战利品、场景种子及当前决策。Battle/Arena 所有声明字段都有清单测试；`scene` 引用和 Arena 的 BGM 是排除项。规则字段未知时拒绝，不默认忽略。
- 保留 Battle/Arena 原 prototype、敌人对象与 roster 的同一引用、参与者 Set、缺失/undefined/null 三种状态。Trainer/Modifier 采用可信注册表，显式字段和目录引用，无构造器、随机生成、堆叠截断或效果回放。组件表保留战利品与修饰器等重复引用。
- Battle RNG 使用原 `captureRandomState/restoreRandomState`；新增房间独立 SceneRandom，使用原 Phaser 纯算法。保存当前场景流状态和 seed/waveSeed/waveCycleOffset/offsetGym；种子作用域使用隔离的临时生成器，保持原外层状态，拒绝异步作用域。
- 决策只接受 `wait-actions`，持有 ID、存活行动席位与每席显式合法选项，验证提交意图与选项精确一致。合法选项必须由可信原规则适配器提供，本模块不自行生成简化战斗菜单。
- 原 `turnCommands` 必须为尚未执行的空命令集合；非空命令队列、待执行效果、学习招式/进化/地图等其他停点明确拒绝。不能从任意 Phase/动画中途保存。
- 已收输入和回执继续由 M1 房间 envelope 保存，与 checkpoint 同一原子文件；正式服务恢复上下文时重新验证每个已收输入的席位、合法性及校验器无副作用。损坏输入在发布快照前拒绝，不改写旧档。

本批上下文是由适配器显式提供的规则对象集合，不是对整个 Phaser BattleScene 进行自动抓取。恢复对象也不是已初始化的显示容器；UI/场景绑定尚未完成。原单人和实验页入口未切换。

## 验收证据

新增 8 项测试（5 单端、3 WS）：

1. AST 核对 Battle/Arena 每个声明字段。
2. 原类/引用/资源/生成池/效果/修饰器及两随机流 JSON 往返，恢复后继续与不中断状态和结果相同。
3. 损坏 RNG、错回合、丢库存、错敌人/行动所有者、遗漏行动席位、未知组件、未知停点和非空队列拒绝，旧模型不变。
4. SceneRandom 与原 withSeedOffset 的随机输出、外层状态一致；两个房间交错执行 20 次无串流。
5. Trainer 与 ExpBoosterModifier 原类恢复，战利品保留共享引用；缺少 codec 或新增未知私有字段拒绝。
6. 两个真实 WS 客户端独立恢复；单方提交后服务重启、原回执重发，结果及随机消费与未中断参考相同，双方资源只扣一次。
7. 结果写盘失败保留完整旧随机状态和双方输入；重同步后只推进一次。
8. 已持久化行动被损坏时拒绝恢复，不发布、不重写旧档。

验收使用原 Battle 随机方法、Arena/Trainer/Pokemon 类与 ExpBoosterModifier 原方法；推进函数是测试用序列，不是原版整回合。测试目录和服务内存存储均为夹具；重启是服务实例重新挂载，不称进程崩溃/真实双机验收。未读取用户房间，未占用 8020。

自动测试合计 92 项通过（既有 84 + 本批 8）。`npm run typecheck`、`npm run build` 通过；构建仍有原项目大包、动态/静态混合导入警告。审查另验证历史遇敌 ID 可在捕获后归入玩家队伍，以及跨玩家共享可变修饰器引用会被拒绝。
