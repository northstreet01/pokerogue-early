# M2 第四批：Modifier 全类登记与恢复修复

基于 `4920f471`，2026-10-13。全类型指 early 中 57 个具体 Modifier 规则类，不包括渲染 ModifierBar；不等于完整 M2 已验收。

## 变更

- `modifier-fields.mjs` 显式登记全部具体/抽象规则类的字段与继承关系，AST 测试核对源声明。`modifier-state.mjs` 还原原 prototype，不调用 Modifier 构造函数、getArgs、apply 或 getMaxStackCount；保存虚拟堆叠、已消耗树果、剩余战斗数、倍率及持有者，保留原版小数 boostMultiplier 和 PP 恢复 -1 哨兵。校验枚举、数值、缺失字段和额外字段。
- `modifier.ts` 提供正式 capture/restore 导出；`modifier-type.ts` 提供类型目录恢复导出。静态类型使用原可信目录工厂重建行为闭包，生成型类型使用八种显式配方：临时能力、基础能力、树果、属性增强、太晶、TM、进化道具和形态道具。只调用经审查的类型元数据构造函数，不调用奖励生成器、不生成 Modifier、不消费随机数。TM 直接按 moveId 重建，避免原 TM 生成器忽略预生成参数的缺陷。
- 类型字段按重建结果核对，保留 id/generatorId/tier 的存在性；未知目录和无目录 ID 类型明确拒绝，不能回退猜测。名称/描述/图标/音效由可信目录再生，不进入类型规则摘要。
- 等待行动检查点升级为内部 payload v2，增加 ModifierType 共享引用组；相同可变类型对象在恢复后仍共享，错误别名拒绝。旧 v1 不自动迁移，保留存档并拒绝。正式传输 envelope 版本仍为 1，两者不同。
- 原 WS 等待行动测试现在使用原 Modifier 生产导出，替换原单一经验道具测试注册器。
