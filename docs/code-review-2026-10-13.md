## 发现及修复

| 严重性 | 发现 | 修复与验证 |
|---|---|---|
| 高 | 实验收藏更新不完整却直接写正式 `data`，可能改变真实图鉴 | 首次连接只复制正式收藏，后续只写 `coop-experiment-data` 和独立账本；测试验证正式数据逐字不变、重复授予去重、跨训练家拒绝覆盖及备份恢复 |
| 高 | WebSocket 缺少连接 error 监听，非法帧可能触发未处理错误而退出服务 | 隔离并关闭异常连接；真实未掩码非法帧测试后仍能新建房间 |
| 高 | 错误哈希触发暂停时若写盘也失败，旧的已确认状态仍可能允许行动 | 增加服务端内存存储故障标记；立即暂停并阻止行动，重新获取完整状态成功落盘后要求双方确认；注入写盘失败回归通过 |
| 中 | 客户端等待 IndexedDB 时连接可能更换，旧消息随后通过全局 socket 确认到新房间 | 快照处理绑定来源连接，异步写入后再次检查连接；模拟处理中更换连接，确认不会串用 |
| 中 | 复制浏览器标签页会复制 sessionStorage 中的租约 owner，从而绕过多页面互斥 | owner 改为每个页面独立随机生成；保留租约互斥测试 |
| 中 | 导出备份对收藏和授予账本分别读取，存在读到不同事务版本的窗口 | 使用一次 IndexedDB 只读事务导出所有存档记录；增加收藏与账本一致快照测试 |
| 中 | 开发服务重启时没有显式关闭自建 WebSocket 服务和等待房间队列 | Vite closeBundle 释放服务并等待写入队列，避免旧服务持续持有连接 |
| 低 | 恢复席位前使用页面缓存的训练家身份校验，可能与连接时读取的档案不一致 | 改为获取当前实验档案后校验席位身份；初始化发现不同训练家时拒绝覆盖 |

另外补充实验授予 IV/性格范围验证、防止重复连接请求、存储故障提示；明确实验页不代表正式合作游戏完成。未改动原图鉴字段、原捕获/孵化/进化链处理函数或原战斗数值。

历史版本已经写入正式收藏的记录保持原样，不自动回滚、删除或重新发放。历史 `coop-grants` 保留供备份与调查；新实验账本使用独立键。旧房间已确认过的历史授予不会为了填充新副本而再次发放。

- `npm run typecheck`：通过。
